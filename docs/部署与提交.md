# 部署与提交

本地功能与报告已可运行；公网链接只有实际发布并通过外部访问后才能填写。

## GitHub

准备一个本人有权限的仓库，建议名称 `Orgacal`。将发布包内容放在仓库根目录，保留app.py、Python模块、requirements.txt、Dockerfile、docs、examples、data/reference及tests。不要上传.venv、个人配置或认证文件、报告快照、原始大型数据压缩包。

GitHub仓库创建与推送需要该平台的有效连接。GitHub用户名只用于定位，不能代替身份验证；不要把密码或令牌写进代码、网址或聊天记录。当前代码已做好发布准备，但未取得可用账号连接时不能声称仓库已发布。

## 魔搭创空间

依据[魔搭官方部署工作流](https://github.com/modelscope/modelscope-skills/blob/main/skills/ms-studio-deploy/SKILL.md)。

1. 登录自己的魔搭账号，创建创空间。
2. 选择与当前依赖匹配的运行环境。锁定依赖要求Python≥3.12，本地测试Python3.13、Gradio6.30.0。Gradio SDK模式需选择相应版本及基础镜像；平台能直接找到全局demo对象。
3. 若SDK基础环境不匹配，可用提供的Dockerfile（Python3.13、7860端口）。魔搭Docker构建可能要求平台账号已完成实名认证及云账号绑定；这类身份环节由本人完成。本机没有Docker引擎，尚未声称容器构建验证通过。
4. 选择可用的免费CPU资源即可；本项目不需要GPU。未取得额外授权时不选择付费资源。
5. 上传/推送代码，触发部署，检查构建与运行日志。Docker模式可能需要显式点部署。
6. 从外部打开页面，实际运行一次计算、换算、批量示例、论文统计、文献示例和报告下载。确认页面及附件均能访问，再复制该创空间的真实地址。

应用无需大模型密钥。在线文献查询需能访问Europe PMC；无法联网时使用本地缓存。容器以普通用户运行，Matplotlib缓存及生成报告写到临时目录。

## 提交前检查

- 项目名称、三人团队信息及“算剪切 · 找安全区 · 量形状”定位一致。
- 物理模型保留未校准状态；假设算例没有标作实验安全建议。
- 论文Roundness与本项目Circularity分开；未知比例尺不编造。
- 统计复算与外部分割验证分别描述；未完成的实验验证如实披露。
- GitHub链接能看到源码、说明与示例；魔搭链接能运行并下载报告。
- 视频及申报材料的格式、大小、截止日期以比赛当前官方要求为准。
